# Granularity
One component/contract = one task: one `path`, one exported type. Split above 1 layer, 3 collaborators, or 1 method group. Never tasks for packages/folders/modules; no invented requirements - trace to the spec.
# Observability is a runtime contract (design it before decomposing)
The strategy of EVERY executable context carries an `observability` object - UNCONDITIONALLY, whether or not the description asks for auditing, logging or visibility: the audit + step-log floor is operational hygiene, never a feature request, and emit refuses a strategy that lacks any surface of it. Abstract, no vendors: which STEP LOGS mark each boundary crossing (with the correlation key that ties them), which AUDIT TRAIL facts must survive as queryable records (actor, action, outcome, timestamp per regulated step), which METRICS answer the operational questions (what counts, what durations, with bounded tags). The active tech-stack skill names the concrete mechanisms.
It is not complete without an EXPORT SURFACE: the object must declare how those logs and records LEAVE the process in a machine-readable form - a named schema (structured event fields, not prose) written to a destination an external collector can consume (log-management tools such as Elasticsearch/Loki, metric scrapers such as Prometheus). The contract is written by the app; shipping/indexing is the platform's job, so the app NEVER hard-depends on the external tool: the default sink is a local append-only structured destination; a direct push endpoint only when the description names one, and then it needs the same offline-substitute treatment as an external database (the boot test passes without the tool running). The sink properties (format, destination, rolling) are operational values -> the CONFIG unit's literal keys.
Decompose it like domain logic - a duty without a unit is prose:
- an audit trail = PORT in domain/application (its record shape and emit method tabled in ast_hints) + ADAPTER in infrastructure +, when queryable, a MIGRATION owned by the database step;
- correlation = one middleware/filter unit at the entry boundary;
- meters = declared in the consuming unit's table (name + what it counts), never a scatter of raw logger calls: a business unit records contractual facts ONLY through planned ports, never ad-hoc text logs;
- a planned STEP LOG is an OWNED artifact, not vocabulary: every strategy `observability.step_logs` entry must be claimed VERBATIM in exactly one implementation unit's `observability.step_logs` field (that unit's coder puts one logger call at that boundary; that unit's tester asserts the captured event). Intent prose that merely mentions the same words claims nothing - an unowned step log is a log line that will never exist (2026-11-13: 5 planned, 0 owned, 0 in the delivered code, every gate green);
- levels/formats/sampling AND the sink's format/destination/rolling are operational values -> the CONFIG unit's literal keys, never code.
Every observability unit gets the same stage 1/2/3 triple, and its tests assert on CAPTURED structured surfaces (record contents, meter values, correlation fields), not on formatted strings - a log line nobody can assert on is a log line nobody can prove exists.
# DAG
Order: value objects -> aggregates -> outbound ports -> use cases -> inbound ports -> controllers -> configuration. `dependsOn` = direct only; cycles => reject. Siblings share or omit deps. Every unit = stage-1 test task + stage-2 code task (engine mirrors stage 3).
# Payload contract (stage-1/2 tasks)
- `ast_hints` = THE API table: `package`; `implements` supertypes; `dependencies` [{type,task_id}] pinned to producers (a pin without one is a plan error; the producer must also be in `dependsOn`); `methods` [{signature,returns[,semantics}] spelling EVERY boundary method the unit provides - all implemented supertype methods + every accessor a pinned consumer touches; returns "" when none; value objects may list []. A member is INSTANCE unless its signature itself begins with `static`: prose like "read CorrelationContext.contextKey()" describes a call, not a binding - consumers that need to stub the member pin it as instance and take the type as a dependency. `semantics` is a note the tester MUST obey (nullability, initial-state encoding): REQUIRED on every entry when the unit's intent rejects null. Testers assert ONLY this table; the validator refuses implements-without-methods: an untabled collaborator makes consumers improvise contradictory signatures.
- `tdd`: >=1 failing case per public method as given/when/then + test class path.
- `constraints`: layer rules + language/framework from the active tech-stack skill.
# Plan validity (emit-refused; seed-002 D1/D2/D3 roots + rerun F2/F4/F5/F9)
A duty the engine cannot execute is not a plan. At emit the validator refuses:
- (a) **Duty ownership**: every file artifact an intent names (config, migration, schema, manifest...) must be that unit's own `path` or another task's `path`. "Also provide <other file>" inside an intent is prose, not a plan - move the duty to the owning unit or schedule a unit for it.
- (b) **Config unit**: when any intent mentions externalized/operational values (framework config-property facility, runtime config file, "externalized config"), a CONFIG UNIT whose path targets the stack's runtime configuration artifact (its shape comes from the active tech-stack skill, e.g. `src/main/resources/application.yml`, `src/config.ts`, `src/settings.py`) MUST be scheduled carrying the seed's literal values in its intent. No config unit = every runtime default is fiction.
- (c) **Request-encoding alignment**: a pinned request-parameter type and the body shape the paired test intent mandates must agree - a streamed collection type binds with streamed-document bodies, an array/collection type with one-array bodies. The decoder can never satisfy both; refusing the pair at emit costs zero sessions.
- (d) **Nullability semantics**: when an intent rejects null on mandatory fields, the producing unit's `methods` entries must each carry `semantics` naming the initial-state encoding (a shipped constant like UNVALIDATED, or a nullable alternative). A null-intolerant value whose only purpose is to receive pre-validation data freezes two contradictory contracts (tester vs coder) with no owner able to fix it.
- (e) **Prose must not fight the table** (rerun F2 - the constructor-PROSE half of the drift the static-rule blocked at write time; the emit validator now refuses BOTH halves): an intent asserting an unconstructible shape ("private constructor", "utility class", "non-instantiable") cannot coexist with instance-bound members - either bind the members `static` in the table or open the constructor; and an intent that names a collaborator call in STATIC form (`Type.member(...)`) is refused when the pinned producer's table binds that member as an instance - spell the call against the INJECTED collaborator (`validator.validate(sample)`) or bind `static` in the producer's table. Two texts, one type: each side's tester writes what its own text says, and no payload can ever satisfy both shapes.
- (f) **Provider closure** (rerun F4): every type a table constructor INJECTS must have a named PROVIDER duty somewhere in the DAG - the producing unit registers itself (the duty spelled in its intent/table), or the wiring/configuration unit spells the provider duty for that exact type (@Bean factory / module export / registration). Injecting a type nobody provides crashes the context the moment the composition root can see it - or worse, boots green around an empty context (see (g)).
- (g) **Composition-root visibility** (rerun F3 + 13:45 slice half): the entry point's package must be an ancestor-or-self of EVERY component package AND of every context-discovering test package (@SpringBootTest-style slices search upwards and IGNORE scan directives - a directive waives only the component-scan half). Prefer the strategy's base package for the entry at scaffold time; the coverage duty otherwise belongs to the scaffold/wiring unit. The assembly gate now refuses both shapes structurally.
- (h) **Config-surface completeness** (rerun F5): a config-unit intent enumerates the FULL surface its paired test pins - when the test asserts several documents/sections (base + each profile), the intent must carry EVERY document with its activation key and literals. And every runtime reader the config ENABLES (a migration runner) must be given its own connection/URL keys in the SAME document or be explicitly disabled in the documents that must not run it: an enabled reader without a configured datasource silently migrates an auto-detected throwaway store while the app writes elsewhere. The duty set ALSO names the stack's test-profile ACTIVATION route (the tech-stack skill's mechanism, e.g. a test-scoped properties file written by the scaffold): documents nothing ever activates are fiction twice - once at boot, once in the coder that "fixes" it by poisoning a base default.
- (i) **Stream egress** (rerun F9): every published stream port the plan exposes (subscriber-facing API) must either name its consumer unit in the DAG or state the boundary explicitly in the strategy (out-of-process subscribers; the in-tree sink is the contract surface). A stream nobody subscribes to drops (or overflow-counts) every event it publishes - a port without a consumer is prose about integration, not a plan for it.
- (j) **Step-log claim coverage** (2026-11-13 - the completeness failure the consistency gates structurally cannot see): every execution-strategy `observability.step_logs` entry must be claimed VERBATIM (exact normalized text) by exactly one stage-2 unit's `observability.step_logs` field; an entry with no owner, a double claim, or a claim of an entry the strategy never planned is refused at emit with the offending string named. A strategy missing any floor surface (correlation_key, step_logs, audit_trail, metrics, export) is refused BEFORE claims are read - the floor is unconditional; only projects with no strategy file at all (legacy boards, unknown stacks) skip the whole rule.
# Fields
id (T<stage>-### from the prompt), path (relative to the domain project root), kind, layer, feature, export (FQN), intent (implementation-ready: context, unit, invariants, error cases, externalized config keys; never fallback literals), dependsOn, project (slug).
# Emission
ALL tasks in ONE JSON array => `python3 <runner> --emit <file>`; on rejection fix every listed error in one rewrite, re-emit once. Never write `blackboard/queue` directly; never reuse ids.
