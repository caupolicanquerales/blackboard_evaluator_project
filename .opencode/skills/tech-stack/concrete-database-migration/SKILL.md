---
name: concrete-database-migration
description: Translates the selected storage technology and persistence strategy into expand-only DDL migration scripts and one infrastructure task handoff per context. Use after database-technology-selection.
---
# Input/Output
Inputs: selection record, persistence strategy, access paths. Outputs: DDL scripts under the RUNTIME-LOADED canonical directory named by the active tech-stack skill (Spring Boot: `services/<slug>/src/main/resources/db/migration/` - the location `classpath:` migrations actually read, NOT a module-root folder nobody loads) + stage-0 task payloads per context. Dialects, types, tool, naming AND script directory come ONLY from the active tech-stack skill. One canonical directory, scripts written there once: never plan a "copy into resources" duty owned by nobody - the emit gate refuses intents naming files no task owns, and an orphaned copy duty leaves the packaged schema empty while boot stays green (2026-11-17 live: scripts lived only at the module root; `classpath:db/migration` loaded nothing; the runtime schema was fiction until the e2e slice exposed it). Forbidden: app source, ORM entities, live execution, editing existing queue files.
# Modeling
snake_case physical names, plural tables from aggregates/entities; PK = strategy's ID scheme (ULID/UUIDv7/auto-increment, concrete type from tech-stack); invariants -> constraints (FK, CHECK, UNIQUE, NOT NULL) in the PRIMARY store only; root aggregates carry `version` non-null default 0; first release EXPAND-ONLY: create tables/indexes/nullable columns - no drops, renames, or non-null backfills; one idempotent, recorded script per step. Secondary stores: only their native schema/index/TTL/lifecycle definitions (never DB DDL for object storage). SCHEMA MIRRORS THE DOMAIN, never lags it: every column whose value the domain produces must be POPULATED BY THE WRITER or GENERATED BY THE DATABASE (identity/default) - a NOT NULL column with neither is a runtime bomb no mocked test can see (seed-002 2026-11-16: `audit_id VARCHAR NOT NULL PRIMARY KEY` with no default, adapter omitted it, EVERY audit insert failed on the first production request while the suite stayed green); CHECK bounds and DEFAULT values must equal the domain's tabled semantics (a domain floor `>= 1` written in DDL as `DEFAULT 0 CHECK >= 0` documents an illegal state), and a column read back into a primitive must be NOT NULL.
# Access paths -> indexes
Keyset: composite (sort, id); equality/range: B-tree; JSON containment: GIN (or partial for fixed predicates); write-heavy tables indexed ONLY for declared query_performance paths; covering index for hot reads; no speculative indexes.
# Handoff (one infra task per context)
Payload: name, technology+version, migration dir+ordering scheme, seed/reference data (if strategy names any), rollback posture (expand-only => forward-fix + backup restore), verification step (boot test / smoke), owner context, open risks. ONE canonical migration directory: if the runtime needs the scripts in a second location, that copy is a NAMED duty of one scheduled unit in the handoff, and the verification step fails when the two byte-sets diverge - a schema the tests execute and a different schema the runtime deploys is two fictions taking turns (2026-11-16: a portability fix applied to the root scripts left the runtime copy broken). Naming/tooling per tech-stack skill. Profile fragments (runner configuration) go ONLY into the runtime property namespace the tech-stack skill names, in files the application actually loads, and must name the consuming config unit; if no scheduled unit reads them, do not write them - an inert fragment is worse than none.
# Checks
Every script expands, never destroys; every constraint maps to a named invariant; every index maps to a declared query; version columns present; non-primary stores carry only their own definitions.
