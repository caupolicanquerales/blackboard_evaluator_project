# Import contracts
Ports (domain/application) import only `reactor.core.publisher.*` + `java.*`; never org.springframework.{web,data.r2dbc,kafka,amqp}. Adapters (infrastructure) implement ports; api depends on application only. I/O contracts return Mono<T>/Flux<T>; never Optional/List/void/Iterable as I/O types. Declare every cross-layer type in the task imports.
# Wiring tasks (plan them explicitly, with dependsOn)
WebFlux routes/controllers + ProblemDetail mapping (api); ReactiveCrudRepository/R2dbcEntityTemplate, messaging bindings, WebClient (infrastructure); Clock/scheduler beans (shared); WebTestClient/StepVerifier (tests); Flyway/R2DBC migration + local runtime (compose/Testcontainers) config. Every process()-style service gets a subscription-bean task wiring source->sink; every port gets a bound adapter task - reject no-caller ports and no-op adapters; subscriptions via SmartLifecycle, disposed on shutdown.
# Correlation across event-loop hops (plan the mechanism, not the habit)
Thread-local MDC does NOT survive scheduler hops in WebFlux. If the strategy's correlation wording promises log-line propagation "via context-propagation", the plan MUST schedule the install duty in a named unit: dependency `io.micrometer:context-propagation` declared in the POM duty + `Hooks.enableAutomaticContextPropagation()` enabled once in the wiring/configuration unit's intent, with `contextWrite(requestId)` at the entry filter - the correlation unit's own table or the wiring unit's duty, never scattered hand-passing. A plan that will not install it amends the strategy BEFORE emitting (plan rule (t): the emit gate carries the strategy's mechanism token into the duties and refuses the mismatch; a negated mention - "no context-propagation library is used" - counts as the divergence, not the duty). Passing the key as an explicit audit-record field is REQUIRED either way; it complements the mechanism, it does not replace it.
# Event bridges
Adapter tasks translate generic transport payloads into the context's typed domain events (strongly-typed at the boundary).
# Backpressure & caches
No unbounded collections: Sinks.many().multicast().onBackpressureBuffer(capacity); capacity + overflow strategy (DROP_OLDEST|ERROR|BUFFER) declared in the task; check EmitResult of tryEmitNext (retry FAIL_NON_SERIALIZED only; FAIL_OVERFLOW -> declared posture). EVERY LOSING PATH IS COUNTED (plan rule (u)): a DROP_OLDEST/ERROR overflow posture, a FAIL_OVERFLOW branch, or an onErrorResume/swallow on a subscriber boundary that continues past a per-event error is a metered event - the task that declares the posture also declares its Micrometer counter (name + bounded tags, e.g. a dropped counter with a stage tag) so the tester can assert the count; an audited-but-uncounted failure is refused at emit - the FAILED audit row survives in the store, the losing pipeline reports a healthy dashboard. DB-backed policy data gets a boot-time preload filling a reactive cache (Mono.cache); empty defaults (Map.of()) forbidden - fail startup on missing required data.
# Blocking traps (forbid in intents)
block()/blockFirst() in request paths; Thread.sleep; busy Flux.interval without scheduler; .subscribe() inside business code; unbounded collectList().
